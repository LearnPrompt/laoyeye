# 执行意图

适合知道该做什么、就是迟迟不动的时候。先走一遍愿望、最好的结果、最可能的内在障碍和计划，再收成一两句今天就能照着做的如果那么。

跟最小实验对着：最小实验是还没定、要拿现实验证，这条是已经定了，只差开始。

## 怎么用

下面代码块里的提示语是原文，逐字使用。代码块里的「我」指用户，「请你」「你」指你自己，照它做事，不要把填好的提示语打给用户看。

- 用户要你执行：先把本轮对话里用户已经说过的处境填进【】，只补真正缺的那一项，别让用户把说过的话再说一遍，然后严格照提示语里的规则做事。它说先别给建议就先别给，说一次只问一个问题就一次只问一个，说按顺序输出就按那个顺序输出。
- 用户要原文（明确说要复制、要粘贴、发我原文、给我提示语这类话才算）：打空白版，【】保持不填，一个字不改。用户只是说「看看这条提示语」「这条是干嘛的」，不算要原文，用一两句说清它干什么、什么时候用，再问要不要现在跑，别直接倒原文。
- 除了明确要原文的情况，其余一律当执行处理。

禁止改写、精简、扩写、翻译、重排、加小标题，禁止把它替换成你自己的流程，也禁止把多轮追问压缩成一次性问卷。用户手上有原始材料（文档、截图、链接、聊天记录）就一并读进来，上下文多不是问题。

## 跑完接哪条

动作是用户自己今天做的，到此为止。如果那么里的动作要交给 agent 去跑，用 Skill 工具唤起 `kaz-leader`。

```markdown
我已经决定要做的事是：【你知道该做、却一直没开始的那件事】。
我希望它变成的样子是：【一句话写下你真正想要的结果】。

请帮我用 WOOP 和执行意图，把这件事变成今天就能照着做的计划。

第一步，按这个顺序问我。一次只问一个，等我答完再问下一个：
1. 愿望：这件事做成，我具体想要什么。
2. 最好的结果：最好的那种结果发生时，我看到什么、感觉到什么。请我在脑子里把那个画面过一遍，再说出来。
3. 内在障碍：我自己这边，最可能让我开不了头的那一个障碍。要内在的，比如「一坐下就想刷手机」「觉得还没准备好」。我说的是别人不配合、环境不允许，请再问一次，直到问到我自己身上的那一个。
4. 计划：碰上这个障碍时，我可以做的一个很小的动作。

第二步，把上面的内容收成 1 到 3 句执行意图。句式固定成：
如果「具体的情境、时间或地点」，那么我就「一个小到马上能做的动作」。
其中必须有一句是专门对付刚才那个内在障碍的。情境要具体到能被碰到，比如「今晚九点坐到书桌前」，不要写「有空的时候」。动作要具体到不用再想一步，比如「打开文档写下标题」，不要写「开始努力」。

最后请输出：
1. 那 1 到 3 句如果那么，每句单独一行，今天就能照着做；
2. 标出哪一句是对付内在障碍的。
```

## 用户要填的位置

- `【一句话写下你真正想要的结果】`
- `【你知道该做、却一直没开始的那件事】`

用户没给全就先问缺的那一条，别自己替他编。
