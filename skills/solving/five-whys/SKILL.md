# 五问法

适合事情已经搞砸了，直接原因也知道了，但心里清楚换个人来大概还是会出同样的错。一次问一个为什么，每层要证据，分叉单独挖，挖到流程、工具、信息、激励这一层再停，最后每个根因配一个能检查的改进动作。

跟逆向法正好一前一后：逆向法在事前列出会怎么死，五问法在事后查清楚是怎么死的。

## 怎么用

下面代码块里的提示语是原文，逐字使用。代码块里的「我」指用户，「请你」「你」指你自己，照它做事，不要把填好的提示语打给用户看。

- 用户要你执行：先把本轮对话里用户已经说过的处境填进【】，只补真正缺的那一项，别让用户把说过的话再说一遍，然后严格照提示语里的规则做事。它说先别给建议就先别给，说一次只问一个问题就一次只问一个，说按顺序输出就按那个顺序输出。
- 用户要原文（明确说要复制、要粘贴、发我原文、给我提示语这类话才算）：打空白版，【】保持不填，一个字不改。用户只是说「看看这条提示语」「这条是干嘛的」，不算要原文，用一两句说清它干什么、什么时候用，再问要不要现在跑，别直接倒原文。
- 除了明确要原文的情况，其余一律当执行处理。

禁止改写、精简、扩写、翻译、重排、加小标题，禁止把它替换成你自己的流程，也禁止把多轮追问压缩成一次性问卷。用户手上有原始材料（文档、截图、链接、聊天记录）就一并读进来，上下文多不是问题。

## 跑完接哪条

改进动作要交给 agent 去落地，用 Skill 工具唤起 `kaz-leader` 写任务书；挖出来的根因说明整个做法从底子上就不对，用 Skill 工具唤起 `first-principles` 重推；改进方案定了想先排一遍雷，用 Skill 工具唤起 `inversion`。

```markdown
这次出问题的事是：【写清楚出了什么事、什么时候、造成了什么后果】。
我已经知道的直接原因是：【写下你目前认定的那个直接原因】。

请陪我用五问法做一次复盘，目标是找到让这件事能发生的系统原因，不是找一个人来背锅。

规则：
1. 一次只问一个「为什么」，等我回答完再问下一个，不要一口气把五个都问完。
2. 每一层的回答都要能拿事实、记录或数据支撑。我给不出证据的，标成「待核实」，不要当成已知往下推。
3. 每一层都问一句：如果当时有人在，换一个人会不会还是出同样的错？会，就继续往流程、工具、信息、激励上挖；不会，再看是不是个人原因。
4. 如果某一层同时有好几个原因，分叉出来，每个分支单独往下问，不要只挑一个顺眼的。
5. 不一定刚好五层。挖到一个能改、改了这类事就不容易再发生的地方就停，不够就继续问。

问完之后请输出：
1. 一条从结果一路倒推到根因的因果链，每一环标明有证据还是待核实；
2. 根因清单，分成「流程」「工具」「信息」「激励」「个人」几类，没有的类别不写；
3. 每个根因配一个改进动作，写清楚谁来做、什么时候之前做完、怎么检查它真的生效了；
4. 一条最容易被大家略过、但最该改的根因，以及为什么容易被略过。
```

## 用户要填的位置

- `【写下你目前认定的那个直接原因】`
- `【写清楚出了什么事、什么时候、造成了什么后果】`

用户没给全就先问缺的那一条，别自己替他编。
