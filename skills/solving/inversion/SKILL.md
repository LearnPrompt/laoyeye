# 逆向法

跟第一性原理互补。第一性原理从基本事实往上推，逆向法从失败往回推。

适合手上已经有一个方案、但心里不踏实，想提前知道它会怎么死。列出保证失败的做法，按破坏力排序，再翻转成规则，最后给一条最容易被忽视的和一个立刻能做的防护动作。

## 怎么用

下面代码块里的提示语是原文，逐字使用。代码块里的「我」指用户，「请你」「你」指你自己，照它做事，不要把填好的提示语打给用户看。

- 用户要你执行：先把本轮对话里用户已经说过的处境填进【】，只补真正缺的那一项，别让用户把说过的话再说一遍，然后严格照提示语里的规则做事。它说先别给建议就先别给，说一次只问一个问题就一次只问一个，说按顺序输出就按那个顺序输出。
- 用户要原文（明确说要复制、要粘贴、发我原文、给我提示语这类话才算）：打空白版，【】保持不填，一个字不改。用户只是说「看看这条提示语」「这条是干嘛的」，不算要原文，用一两句说清它干什么、什么时候用，再问要不要现在跑，别直接倒原文。
- 除了明确要原文的情况，其余一律当执行处理。

禁止改写、精简、扩写、翻译、重排、加小标题，禁止把它替换成你自己的流程，也禁止把多轮追问压缩成一次性问卷。用户手上有原始材料（文档、截图、链接、聊天记录）就一并读进来，上下文多不是问题。

## 跑完接哪条

规则清单出来了、方案站得住，用 Skill 工具唤起 `kaz-leader` 写任务书开始派活；致命点太多、整个方案站不住，用 Skill 工具唤起 `first-principles` 回到基本事实重推。

```markdown
我要评估的计划/方案/决策是：【填写你正在推进或打算推进的计划、方案或决策，写清目标和现状】。

请用逆向法帮我检验它的健壮性。

第一步，列出 5 到 7 个如果想让这件事保证失败的做法。每条要足够具体，不要写泛泛的「不努力」「没计划」，要写成一个能照着执行就一定会把事搞砸的操作。

第二步，按破坏力从大到小排序，说明每条为什么能致命。

第三步，把每条翻转过来，变成一条必须遵守的规则。翻转要具体到能检查、能执行，不要变成「注意 XX」这种空话。

最后请输出：
1. 翻转后的规则清单，按优先级排列；
2. 这些规则里最容易被忽视的那一条，以及它为什么容易被忽视；
3. 一个现在就能做的防护动作。
```

## 用户要填的位置

- `【填写你正在推进或打算推进的计划、方案或决策，写清目标和现状】`

用户没给全就先问缺的那一条，别自己替他编。
