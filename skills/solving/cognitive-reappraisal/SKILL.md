# 认知重评

适合被一句评论、一次否定困住，反复转「我是不是不行」的时候。一次只问一个问题，把自动想法的原句、情绪分数、支持和反对的证据摆开，再写一句更平衡的替代想法。

跟事实核查对着：事实核查查的是别人的说法，这条查的是你自己脑子里那句话。提到自伤或者已经撑不住，这条会停下来，建议找专业的人。这不是治疗。

## 怎么用

下面代码块里的提示语是原文，逐字使用。代码块里的「我」指用户，「请你」「你」指你自己，照它做事，不要把填好的提示语打给用户看。

- 用户要你执行：先把本轮对话里用户已经说过的处境填进【】，只补真正缺的那一项，别让用户把说过的话再说一遍，然后严格照提示语里的规则做事。它说先别给建议就先别给，说一次只问一个问题就一次只问一个，说按顺序输出就按那个顺序输出。
- 用户要原文（明确说要复制、要粘贴、发我原文、给我提示语这类话才算）：打空白版，【】保持不填，一个字不改。用户只是说「看看这条提示语」「这条是干嘛的」，不算要原文，用一两句说清它干什么、什么时候用，再问要不要现在跑，别直接倒原文。
- 除了明确要原文的情况，其余一律当执行处理。

禁止改写、精简、扩写、翻译、重排、加小标题，禁止把它替换成你自己的流程，也禁止把多轮追问压缩成一次性问卷。用户手上有原始材料（文档、截图、链接、聊天记录）就一并读进来，上下文多不是问题。

## 跑完接哪条

替代想法和那个小动作用户今天自己做得了，到此为止。小动作知道会拖，用 Skill 工具唤起 `implementation-intention`。小动作要交给 agent 干，用 Skill 工具唤起 `kaz-leader`。

```markdown
我现在卡住的情境是：【写清发生了什么、谁说了什么】。
我脑子里反复出现的那句话是：【自动冒出来的原句，不要修饰】。

请陪我做一次认知重评，把这句自动想法核一遍。这不是治疗。如果我提到伤害自己、不想活，或者难受已经严重到没法做这个记录，请停下来，告诉我去联系身边能帮忙的人，或者找专业的心理帮助，不要继续往下问。

规则：
1. 一次只问一个问题，等我回答完再问下一个，不要把整张记录一次倒给我。
2. 自动想法要原句。我说得含糊，就追问那句原话，不要替我改写成更体面的说法。
3. 证据只收我举得出的具体事实。我说「他们肯定觉得我差」却举不出事实，标成「这是猜测」，不要当成证据。
4. 思维偏差有就点名，没有就写没有。常见的有：全或无、灾难化、读心、过度概括、情绪推理、贴标签、应该句式、把什么都揽到自己身上、只看见负面。不要为了凑数硬套。

按这个顺序问：
1. 情境里还有哪一句事实我没说清。
2. 自动想法的原句，一个字不改地确认一遍。
3. 此刻的情绪叫什么，强度从 0 到 100，100 是最强。
4. 有哪些事实支持这句想法。
5. 有哪些事实反对这句想法。
6. 上面这些里，有没有思维偏差，有的话叫什么名字。
7. 请我写一句更平衡的替代想法。它要同时装得下支持和反对两边的事实，不要写成空洞的加油，也不要假装坏事没发生。
8. 用同一个 0 到 100，给现在的情绪重新打分。

最后请输出：
1. 那句更平衡的替代想法；
2. 一个今天就能做的很小的动作，小到五分钟内能做完。
```

## 用户要填的位置

- `【写清发生了什么、谁说了什么】`
- `【自动冒出来的原句，不要修饰】`

用户没给全就先问缺的那一条，别自己替他编。
