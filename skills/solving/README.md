# 解决问题

问题问清楚了，接下来是解。

## 模型可唤起

你说到相关的事，Agent 自己就会拿出来用。

- **[专家会诊](./expert-panel/SKILL.md)**（`expert-panel`）：组一个真正互补的专家团，然后让他们互相质疑。
- **[第一性原理](./first-principles/SKILL.md)**（`first-principles`）：别再打补丁了，拆回最底层重新推一遍。
- **[跨领域借解](./cross-domain-borrow/SKILL.md)**（`cross-domain-borrow`）：你这个问题，别的行业可能十几年前就解决了。
- **[逆向法](./inversion/SKILL.md)**（`inversion`）：先列出怎么做保证失败，再把每条翻成必须遵守的规则。
- **[五问法](./five-whys/SKILL.md)**（`five-whys`）：失败了别急着找人背锅，一层层问为什么，挖到能改的系统原因。
- **[认知重评](./cognitive-reappraisal/SKILL.md)**（`cognitive-reappraisal`）：被一句话困住的时候，把那句自动想法核一遍，写出更站得住的一句和一个小动作。
- **[自建框架再自查](./self-framing/SKILL.md)**（`self-framing`）：先为这件事现写一套分析框架，跑完再查自己漏了什么。
- **[二三阶影响](./second-order-effects/SKILL.md)**（`second-order-effects`）：改动的直接效果之外，把二阶、三阶影响推演出来。
- **[最强反对者](./strongest-opponent/SKILL.md)**（`strongest-opponent`）：先假设当前最合理的方案是错的，站到最强反对者那边找能推翻它的东西。
- **[历史包袱](./historical-baggage/SKILL.md)**（`historical-baggage`）：顺着 Git 历史和关键 PR，找出可以安全移除的历史包袱。
- **[认知成本](./cognitive-cost/SKILL.md)**（`cognitive-cost`）：按一个能干但不了解项目的工程师来接手，评估读懂要付的认知成本。
- **[慢PR排查](./slow-pr-review/SKILL.md)**（`slow-pr-review`）：看最近一段时间里最慢的几个 PR，找卡顿和能优化的地方。
- **[共性复盘](./common-cause-retro/SKILL.md)**（`common-cause-retro`）：把一段时间里的 Bug、返工、回滚和重复修改放在一起，找出共同根因。
- **[诊断 diagnosing-bugs](./matt-diagnosing-bugs/SKILL.md)**（`matt-diagnosing-bugs`，收录自 mattpocock-skills）：先拿到一个能稳定复现的红灯，再谈任何理论。修完带回归测试。
- **[点子王 idea-king](./carl-idea-king/SKILL.md)**（`carl-idea-king`，收录自 partner-skill）：第一性原理拆解加对抗式审查，方案成型之后找人拆台用。
