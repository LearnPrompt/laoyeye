# 共性复盘

复盘一段时间里的一批 Bug、返工、回滚和重复修改。不只统计发生了什么，要看背后有没有共同根因，把能预防的共性问题沉淀成项目规则、自动化或者 Skill。原文时间窗写成 XX时间。会读近期记录。

五问法针对已经发生的一件事。这条看一批问题的共性。

## 怎么用

下面代码块里的提示语是原文，逐字使用。代码块里的「我」指用户，「请你」「你」指你自己，照它做事，不要把填好的提示语打给用户看。

- 用户要你执行：直接按提示语里的角色和流程走。它说先别给建议就先别给，说一次只问一个问题就一次只问一个，说按顺序输出就按那个顺序输出。
- 用户要原文（明确说要复制、要粘贴、发我原文、给我提示语这类话才算）：把整段原样打出来，一个字不改。用户只是说「看看这条提示语」「这条是干嘛的」，不算要原文，用一两句说清它干什么、什么时候用，再问要不要现在跑，别直接倒原文。
- 除了明确要原文的情况，其余一律当执行处理。

禁止改写、精简、扩写、翻译、重排、加小标题，禁止把它替换成你自己的流程，也禁止把多轮追问压缩成一次性问卷。用户手上有原始材料（文档、截图、链接、聊天记录）就一并读进来，上下文多不是问题。

## 时间窗

原文写的是 `XX时间`。代码块里这几个字保持原样。用户已经给了时间范围，执行时只把 `XX时间` 换成用户说的范围，句子其余部分一个字不改。用户没给，先问一句再跑。用户要原文时，`XX` 留着不填。

「怎么用」里说直接按提示语走，约束的是 `XX时间` 以外的每个字。

## 会读记录

这条会去读近期的 Bug、返工、回滚和重复修改。路由指到它之前，不确定就先问用户。单独一件已经发生的事要一层层问为什么，用 Skill 工具唤起 `five-whys`。

## 跑完接哪条

要沉淀成规则、自动化或 Skill，用 Skill 工具唤起 `kaz-leader`。同时发现文档、规则和记忆已经跟代码对不上，用 Skill 工具唤起 `kaz-neat-freak`。某一件单独的事故还要往下挖，用 Skill 工具唤起 `five-whys`。

```markdown
全面复盘最近XX时间的 Bug、返工、回滚和重复修改。不要只统计发生了什么，要分析这些问题背后有没有共同的根因。把能够预防的共性问题沉淀成项目规则、自动化或者Skill，避免我们反复支付同样的成本。
```
